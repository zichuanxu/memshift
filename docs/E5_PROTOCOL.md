# E5 黑盒 (D, B) 推断协议（预注册草案，写入 prereg v1 前冻结）

依据：计划 §6 E5 的五条要求——(1) 先在白盒 HoldMem 四格上验证推断探针，报告混淆矩阵，达标线 Cohen κ ≥ 0.7；(2) 推断与测量用不相交的两半知识项；(3) 干预在适配器层做，不走系统删除 API；(4) 两次独立摄入建立噪声地板；(5) 不保留原文的配置直接声明不可识别。

## 1. 推断探针

**B 探针（孤儿测试）**：取推断半集中的结构化知识项（周期日程、预约、任务到期、联系人属性），在适配器层把其 gold 依赖对象以源删除事件送入（与自然流一样作为一次 `ingest`：墓碑事件，文本 "Record <id> was deleted on <ts>"），随后按正常节奏维护。gold 变为 abstain。
- 观测量：孤儿坚持率 P = P(系统仍给出旧值 | 依赖被删除)。
- 判定：P ≤ 0.5 → B=1（系统检测到依赖消失）；P > 0.5 → B=0。阈值在白盒上校验。
- 白盒预期：B=1 格重派生后无支撑 → abstain；B=0 格旧项永不失效 → 坚持旧值。

**D 探针（结构化修复精确率）**：对推断半集中有规则抽取器的结构化项（联系人属性、日程、任务到期），施加 S_src 修订（值改变而非删除），在系统已对该项作出更新后，看更新值是否与结构化源完全一致。
- 观测量：R = P(更新值 ContractValid | 系统给出了新值)。
- 判定：R ≥ 0.98 且系统导出记录中带类型化值与可解析的源引用 → D=1；否则 D=0。结构判据来自 `export_raw()`：记录是否同时保留类型化值（非自然语言）与可定位到源文本的片段。
- 白盒预期：D=1 格的兜底使结构化修复精确；D=0 格受写入模型误差影响。

**标签层级**：B 与 D 各自给出 {0, 1, 不可识别}。任何一项探针在该系统上的有效样本 < 20 项时记为不可识别；配置不保留原文或源元数据时两项都不可识别（计划 §6 E5 (5)）。

## 2. 白盒验证

对开发集 HoldMem 四格（源纪元粒度）逐格施加两类探针，得到推断标签；与真实 (D, B) 比较，报告 2×2 → 2×2 混淆矩阵与 Cohen κ。κ < 0.7 的那一维（B 或 D）在原生系统上只作描述，不进入充分统计量检验。

## 3. 充分统计量检验

- 测量半集上，原生系统在 S_src、S_def、S_wr 下的 carryover（Update、Stability、Retention）。
- 预测值：白盒格中与其推断 (D, B) 相同的格在同一世界、同一 shift 下的 carryover；预测区间取白盒格在世界层面的 95% bootstrap 区间。
- 判定：原生系统 carryover 落在预测区间内 → 与充分统计量一致；落在区间外 → 报告为理论边界（偏差方向与大小）。

## 4. 成本控制（§9 规则 2、§12）

- 每个原生系统在每个世界只做一次前缀摄入（到 t_f），立即做一次状态快照；S_src、S_def、S_wr 分支都从快照恢复后继续。
- 先在 1 个世界实测原生 t_i（每事件 LLM 调用数与 token），再按预算决定世界数（计划起点 30，§12 备选：只留一个原生系统或缩到 15 世界）。
- 两次独立摄入只在 3 个世界上做，用于噪声地板。
